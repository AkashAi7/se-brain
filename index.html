🧠 SE Brain

An LLM-powered personal wiki system that turns scattered web research into a structured, interlinked, citation-grounded knowledge base — entirely managed by an AI agent inside VS Code.

What Is SE Brain?

SE Brain is a Software Engineering knowledge management pattern. You point the AI at a topic, it researches it on the internet, saves the raw sources, then compiles them into a richly interlinked wiki — complete with concept pages, entity profiles, comparisons, cross-references, and contradiction tracking. Every claim traces back to a source. The wiki grows incrementally as you add more sources or ask more questions.

The Core Idea: Two Layers

The system separates immutable source material from LLM-generated synthesis, so you always know what's a raw fact vs. what's a compiled analysis.

raw/ Immutable

User-curated source documents fetched from the web. The LLM reads these but never modifies them.

  • Each source is a markdown file with YAML frontmatter (title, URL, date, type, tags)
  • sources.md — a manifest cataloging every source
  • assets/ — downloaded images and binary files
  • Once written, a source file is never changed (append a -v2 for updates)

wiki/ LLM-Owned

AI-generated, structured, interlinked wiki. The LLM creates, updates, and maintains this entirely.

  • sources/ — one summary page per raw source
  • concepts/ — synthesized topic pages across multiple sources
  • entities/ — people, organizations, tools, places
  • comparisons/ — side-by-side analyses
  • analyses/ — filed answers to user questions
  • index.md — master catalog & log.md — append-only changelog

The user directs; the LLM executes. Clear separation of roles keeps the system reliable.

The 7 Skills

Skills are modular instruction sets that teach the LLM how to perform each part of the workflow. Each skill is a SKILL.md file with trigger phrases, prerequisites, and step-by-step workflows.

🔍

open-research

Scours the internet for articles, papers, and data on a given topic. Converts each to clean markdown with YAML frontmatter and saves them as immutable files in raw/. Builds the source manifest.

research X gather sources find papers on collect articles
🏗️

wiki-generator

Reads every raw source and compiles the wiki/ — source summaries, concept pages, entity profiles, comparisons, overview, index, and changelog. Updates incrementally when new sources arrive.

build the wiki ingest sources update wiki create wiki pages
💬

query-wiki

Answers questions by searching the wiki index, reading relevant pages, and synthesizing cited answers. Substantial answers get filed as wiki/analyses/ pages so insights compound over time.

what does the wiki say about compare X and Y analyze X summarize what we know
🩺

lint-wiki

Runs 7 health checks: orphan pages, dead links, stale content, contradictions, coverage gaps, missing backlinks, and index consistency. Auto-fixes safe issues; asks before fixing warnings.

lint the wiki health-check find broken links find gaps
📧

work-research

Gathers sources from internal workplace data — Outlook emails, Teams messages, meetings, and shared documents via the WorkIQ MCP server. Saves results to raw/ with a work-- prefix for easy identification.

check work emails about find internal context on what did the team discuss gather internal sources
🎨

html-explainer

Converts dense markdown — wiki pages, raw sources, or LLM responses — into polished, self-contained HTML explainer pages with dark theme, visual hierarchy, and responsive design. Saves to html-files/.

visualize this make an HTML explainer convert to HTML generate a visual summary
🧩

make-skill-template

A meta-skill for creating new skills. Scaffolds the folder structure, generates SKILL.md with proper frontmatter, and supports bundled scripts, references, and assets.

create a skill scaffold a skill make a new skill

The Compounding Loop

The system is designed so that everything compounds. New sources strengthen existing concept pages. Answered questions become analysis pages that future queries can reference. Lint runs surface gaps that drive new research. The wiki gets richer with every interaction — it's not just a static dump, it's a living knowledge base.

Core Principles

Six rules that keep the wiki trustworthy and maintainable.

  1. Never modify raw/. Source files are immutable. Only sources.md (the manifest) gets updated.
  2. Every claim traces to a source. No hallucinated facts. Every wiki statement is grounded in a raw source document.
  3. Flag contradictions, don't resolve them. When sources disagree, show both sides with citations. The user decides.
  4. Update incrementally. When new sources arrive, update existing pages — don't regenerate the whole wiki.
  5. Maintain cross-references. Every page links to related pages. Backlinks stay current. The index reflects reality.
  6. Explorations compound. Filed analysis pages are as valuable as ingested sources — they build the knowledge base over time.

Example Session

Here's what a real session might look like:

👤 You:

"Research the CAP theorem and distributed consensus algorithms"

🤖 Agent (open-research):

Fetches 8 sources → saves to raw/ → updates sources.md

👤 You:

"Build the wiki"

🤖 Agent (wiki-generator):

Creates 24 pages: 8 source summaries, 6 concepts (CAP theorem, Paxos, Raft, …), 7 entities (Leslie Lamport, …), 2 comparisons, 1 overview

👤 You:

"How does Raft differ from Paxos?"

🤖 Agent (query-wiki):

Reads index → finds concept pages → produces comparison table with citations → offers to file as wiki/analyses/raft-vs-paxos.md

👤 You:

"Lint the wiki"

🤖 Agent (lint-wiki):

Finds 2 orphan pages, 1 missing backlink, suggests creating a page for "Byzantine fault tolerance" (mentioned in 4 sources)
