# MCEM Deal Execution

## Definition

The **Microsoft Customer Engagement Methodology (MCEM)** is Microsoft's unified selling motion, defining how opportunities move from qualification to close and how each role (AE, SE, CSA, SSP) contributes at each stage. For SEs it defines when to engage, what a technical win means, and how work maps to pipeline progression (from [MCEM Framework](../sources/mcem-deal-execution-framework.md)).

## Key Points

- **Five stages (SE lens):** Qualify (light) → Develop (medium) → Solution (heavy) → Proof (heavy) → Close (light), each with defined activities and success criteria.
- **Stage-weighted SE involvement** — the SE is heaviest in Solution and Proof, where workshops, POCs, demos, and objection handling earn the [technical win](technical-win.md).
- **Pipeline hygiene matters** — aging beyond 2 weeks with no progress signals stall risk; undefined POC success criteria signal scope-creep risk.
- **Deal reviews follow a 6-part structure:** Situation, Technical status, Compete, Proof plan, Risks, Ask.
- **Partner/co-sell** — bring in ISV/SI partners for capacity, marketplace/MACC eligibility, and co-sell credit.

## MCEM Stages (SE Perspective)

| Stage | SE Involvement | Success Criteria |
|-------|---------------|-----------------|
| Qualify | Light — validate technical fit | Technical qualification confirmed |
| Develop | Medium — build the case | Requirements understood; approach defined |
| Solution | Heavy — prove the value | Technical win declared |
| Proof | Heavy — remove doubt | All technical objections resolved |
| Close | Light — support final steps | Deal closed; clean handoff |
